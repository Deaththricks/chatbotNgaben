## Problem 1 — Not enough definitions, and a few are broken

**Severity: HIGH**

**What it is.** A "definition" is the one-line *what is this* text on each
entity. Only 76 of 305 have one. A few that exist are gibberish:
- `bale salunglung` → *"wilayah kantongnya segala sesuatu yang didetasering di dunia ini"*
- `pawedan` → *"shiwa ( dewa ) loka"*

**Why it happened.** `build_kb.py` looks for definitions in only one place:
sentences the extractor tagged with the `BERARTI` ("means") relation. That
relation was often noise, so when it's the only source you get a garbled
definition — and most entities have no `BERARTI` sentence at all, so they get
nothing.

**Why it matters.** If a chatbot user asks *"apa itu pawedan?"*, the bot wants
a clean definition to answer with. Three of four entities can't give one, and a
handful would answer with nonsense.

**The fix.** In `build_kb.py`: also mine definitions from `passages.jsonl` —
the first sentence of the form *"X adalah / ialah / yaitu …"*. And discard a
definition when its only source is a low-quality `BERARTI` literal.

## Problem 2 — Junk values in the attribute lists

**Severity: MEDIUM**

**What it is.** Each entity has an `attributes` list (e.g. *bade → memiliki →
11 tingkat*). Some values are meaningless:
- `bale pamuunan` → "disertai: **de facto**"
- `kuburan` → "dikenai: **tulang belulang**"
- `bale salunglung` → "menjadi: **rumah**"

**Why it happened.** These come from the dependency parser grabbing the wrong
words. `build_kb.py` has a filter (`weak_literal`) that drops *very* short
values (1 word, closed-class), but two-word junk like "de facto" slips through.

**Why it matters.** Mostly cosmetic — the glossary looks sloppy and a graph
query on that entity returns noise. Nothing breaks.

**The fix.** In `build_kb.py`: strengthen `weak_literal()` to also drop adverb
phrases (`de facto`, `arah hulu`, `\d+ kali`) and values with no head noun.

## Problem 3 — 123 entities the script couldn't identify (40%)

**Severity: MEDIUM**

**What it is.** When `build_kb.py` sees a term it matches it against
`Data\ngaben-dictionary.json` (765 terms). 123 didn't match. Two kinds:

- **3a — real terms just missing from the dictionary (~100):** `canang sari`,
  `bhuta kala`, `hyang prajapati`, `pura desa`, `pura puseh`, `pura mrajapti`,
  `dewa wishnu`, `karma wasana`, `sasih kaenem/kapat/kasa/katiga`,
  `wuku kuningan`, `lontar yama purwana tatwa`… These *did* land in the KB with
  a guessed type and often a parent link — they work — they're just flagged.
- **3b — genuine fragments (~15):** `atas takir bersama`, `bade sawa atas`,
  `tiga hari ngaben`, `pabersihan hidup tangan jenazah/layon`,
  `lubang satu uang kepeng`, `sudut atap bade`, `rurub sinom tadi`.

**Why it happened.** The dictionary was built for an earlier pass and doesn't
cover everything in the corpus. The fragment filter isn't exhaustive.

**Why it matters.** 3a — minor; they work, they're just not "certified", and
duplicates of them can't be merged reliably. 3b — clutters the graph with
non-entities, same as the fragments already in the review queue.

**The fix.** Add the ~100 real terms to `Data\ngaben-dictionary.json`
(`"term": "TYPE"`). Add the ~15 fragments to a drop-list (in
`normalize.py`'s fragment rules or `build_kb.py`).

## Problem 4 — A few review fixes produced phrase-nodes

**Severity: MEDIUM**

**What it is.** Six of the review `fix:` decisions had an *object* that is a
phrase, not a single thing, so the build turned the whole string into a node:
- `rumah_atau_bale_banjar` (from "rumah atau bale banjar")
- `bhatara_bhatari` (two gods)
- `tirtha_dan_sajen_kecil`, `dipan_kamar_tidur`, `pengambilan_air`,
  `rateng saha salaran sejangkep`

**Why it happened.** The review pass only fixed the *format* of the decisions
(capitalisation, punctuation), not the content. So each phrase went in verbatim
and became a node id.

**Why it matters.** ~6 nonsense nodes in the graph. The fact *sentences* read
fine — it's only the node they point at that's junk.

**The fix.** Re-edit those 6 entries in `kb\review_queue.jsonl` — split each
into separate edges, or `reject`. Then `python kb\apply_review.py` +
`python kb\build_kb.py`.

The 6 keys: `2183|bale salunglung|bale banjar`, `2986|pitra|bhatara`,
`2623|sekah kangsen|tirtha`, `3843|galar|harapan`, `1889|pabersihan|hari pabersihan`,
`631|banten panebusan|rateng saha salaran sejangkep`.

## Problem 5 — A handful of wrong entity types

**Severity: LOW**

**What it is.**
- `merajan kawitan` → tagged `KONSEP_FILOSOFIS`; it's a **temple** (`BANGUNAN_RITUAL`)
- `pitra yadnya nglungah`, `pitra yadnya tahap berikutnya` → tagged `RITUAL`;
  should be `RITUAL_KEMATIAN` to match the rest
- `bali dataran` → tagged `"Place"` (odd casing; elsewhere it's `PLACE`)

**Why it happened.** For terms not in the dictionary, the type is guessed from
how the extractor labelled them in sentences — and those labels were
inconsistent.

**Why it matters.** Small — affects node colour and "list all temples" queries.
~4 entities.

**The fix.** Add them to `Data\ngaben-dictionary.json` with the correct type
(same fix as Problem 3).

## Problem 6 — The graph is spread out

**Severity: LOW (structural, largely unfixable)**

**What it is.** 77 of 305 nodes have no connections; only ~130 sit in the main
connected component.

**Why it happened.** Many terms in the source appear exactly once, in a purely
descriptive sentence — there's no second mention to link them to anything.

**Why it matters.** Limits graph-walking (can't traverse A→B across islands).
For a plain search / RAG chatbot it doesn't matter.

**The fix.** None, short of feeding in more source documents. This is a property
of the corpus, not a bug.

---

## Problem 7 — Clumsy wording on the DIKENAI relation

**Severity: COSMETIC**

**What it is.** `DIKENAI` renders as *"X dikenai tindakan ritual terkait Y"* —
awkward Indonesian. 24 facts use it.

**Why it happened.** `DIKENAI` is a catch-all for ~20 different action verbs
(wrapped, washed, carried, smeared…). No single phrase fits all of them.

**Why it matters.** Cosmetic — affects only the `text` field in `facts.jsonl`.
The real citation (`source_sentence`) is always attached and correct.

**The fix.** Pick a cleaner template in `kb\relation_phrases.json`, or leave it.

## Problem 8 — 10 fragments stuck in the review file

**Severity: NONE (housekeeping)**

**What it is.** `kb\review_queue.jsonl` still lists 10 entries (`harapan`,
`nama upanisad`, `tata cara penguburan biasa`…) with blank `decision` fields,
even though `reject` was written on them earlier.

**Why it happened.** These are a different record type (`fragment_entity`) and
`apply_review.py` only processes the edge records — it skips these.

**Why it matters.** Zero — they are **already excluded** from the KB. The file
just looks unfinished.

**The fix.** Small tweak to `apply_review.py` to handle keyless
`fragment_entity` records (accept `keep` / `reject`), or ignore it.
